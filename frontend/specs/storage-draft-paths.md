# Storage draft paths

## Application Overview

MiBolt storefront checkout behaviour for E016 from docs/spec/test-scenarios.md. The scenario covers the user flow of entering contact and address data into the checkout, reloading the page, and verifying that the typed data does not survive a reload, while the cart is retained. The mock keeps its state in the browsing context's sessionStorage under mi-bolt.snapshot.default; the checkout draft (contact, billing, delivery, payment) is kept there only while a card payment waits for the payment page. A reload of /penztar/szallitas redirects the user to /penztar/adatok?navigationReason=incomplete, contact fields are empty, navigation-reason banner reads "Előbb ezt a lépést kell kitöltened, utána léphetsz tovább.", the cart page still shows the Motorola Edge 50 Fusion (1 db, 89 990 Ft) item, and the sessionStorage holds the cart only — none of the typed strings appear.

## Test Scenarios

### 1. MiBolt storefront — storage draft on reload

**Seed:** `e2e/seed.spec.ts`

#### 1.1. [E016] contact and address typed into the checkout are gone after a reload, the cart is kept

**File:** `e2e/integration/storage-draft-reload.spec.ts`

**Steps:**

1. Open the storefront on a fresh page at viewport 1920x1080 (Full HD). - expect: The home page loads at http://localhost:4401/ and the header shows "Kosár 0" with aria-label "Kosár megnyitása, jelenleg üres". - expect: sessionStorage holds no key named mi-bolt.snapshot.default, or holds it with no items array.
2. Click the "Mobiltelefonok" link in the primary navigation. - expect: The page lands on http://localhost:4401/telefonok and the section heading reads "Mobiltelefonok". - expect: A grid of catalogue cards is rendered as <article> elements, each carrying a data-testid="product-card-cta" link with the text "Megnézem".
3. Pick the first catalogue card on the page (the one whose product-card-cta is the first in the result list), open it by clicking its data-testid="product-card-cta". - expect: The product page heading is the H1 of the chosen card. - expect: The data-testid="add-to-cart-button" wraps an inner <button> with the text "Kosárba teszem" and that inner button is visible in the viewport (≥ 1024 px width). - expect: A data-testid="purchase-cta" also exists on the page but is not the visible add control at this width.
4. Click the inner <button> of data-testid="add-to-cart-button". - expect: The header cart link text changes to "Kosár 1" and its aria-label becomes "Kosár megnyitása, 1 termék".
5. Navigate to the cart via the header cart link at href="/penztar/kosar". - expect: The page is the checkout cart at http://localhost:4401/penztar/kosar with H1 "A kosarad". - expect: The cart contains exactly one line: the previously chosen product, "1 db", "Részösszeg 89 990 Ft". - expect: The stepper "Pénztár lépései" lists "1 Kosár", "2 Adatok", "3 Szállítás", "4 Ellenőrzés" with step 1 not yet marked done.
6. Click the "Tovább az adatokhoz" button in the order summary. - expect: The page is the contact step at http://localhost:4401/penztar/adatok with H1 "Kapcsolattartási adatok". - expect: Three inputs are present: data-testid="contact-fullname-input" (label "Teljes név *"), data-testid="contact-email-input" (label "E-mail cím *"), data-testid="contact-phone-input" (label "Telefonszám *"), and the data-testid="contact-submit" wrapper around an inner button with the text "Tovább a szállításhoz".
7. Type "Teszt Béla" into data-testid="contact-fullname-input". - expect: The input's value is "Teszt Béla".
8. Type "teszt.bela@example.test" into data-testid="contact-email-input". - expect: The input's value is "teszt.bela@example.test".
9. Type "+36201234567" into data-testid="contact-phone-input". - expect: The input's value is "+36201234567".
10. Click the inner button of data-testid="contact-submit" (text "Tovább a szállításhoz"). - expect: The page is the delivery step at http://localhost:4401/penztar/szallitas with H1 "Átvétel és fizetés". - expect: The stepper marks steps "1 Kosár" and "2 Adatok" as "Kész" (check), and step "3 Szállítás" is the current step. - expect: Two radios are visible: "Házhoz szállítás 0 Ft" and "Átvételi pont 0 Ft"; two radios: "Bankkártya 0 Ft" and "Utánvét 490 Ft".
11. Click the "Házhoz szállítás" radio in the "Szállítási mód" group. - expect: The "Házhoz szállítás" radio is checked and the "Szállítási mód" row of the right-hand summary reads "Házhoz szállítás". - expect: A "Szállítási cím" group appears with inputs data-testid="address-input-postalCode" (label "Irányítószám"), data-testid="address-input-city" (label "Város"), data-testid="address-input-line1" (label "Cím (utca, házszám)") and data-testid="address-input-line2" (label "Emelet, ajtó (opcionális)"), with the country "HU – Magyarország".
12. Without leaving the step, type "1111" into data-testid="address-input-postalCode". - expect: The postal-code input's value is "1111".
13. Without leaving the step, type "Budapest" into data-testid="address-input-city". - expect: The city input's value is "Budapest".
14. Without leaving the step, type "Teszt utca 42." into data-testid="address-input-line1". - expect: The street input's value is "Teszt utca 42.".
15. Read sessionStorage["mi-bolt.snapshot.default"] before reloading. - expect: The stored JSON document is the cart snapshot (cartId, one item with the chosen variantId and quantity 1, no contact or address fields). - expect: The snapshot holds none of the typed strings: "Teszt Béla", "teszt.bela@example.test", "+36201234567", "1111", "Budapest", "Teszt utca 42." are all absent. - expect: Record the current URL http://localhost:4401/penztar/szallitas as the URL to reload.
16. Reload the page by navigating to page.url() (the same URL recorded in the previous step). - expect: The browser lands on http://localhost:4401/penztar/adatok?navigationReason=incomplete with title "MiBolt — Kapcsolattartási adatok". - expect: The data-testid="navigation-reason" banner shows the text "Előbb ezt a lépést kell kitöltened, utána léphetsz tovább." - expect: The contact step fields are empty: data-testid="contact-fullname-input" value "", data-testid="contact-email-input" value "", data-testid="contact-phone-input" value "". - expect: The stepper marks step "1 Kosár" as "Kész" and "2 Adatok" as the current step (no check mark on step 2), with "3 Szállítás" and "4 Ellenőrzés" still pending. - expect: sessionStorage["mi-bolt.snapshot.default"] still exists, the cart is unchanged (same cartId, same single item, quantity 1), and the snapshot holds none of the typed strings: "Teszt Béla", "teszt.bela@example.test", "+36201234567", "1111", "Budapest", "Teszt utca 42." are all absent. - expect: The header's cart badge on the shop front (after navigating back to http://localhost:4401/) still reads "Kosár 1" with aria-label "Kosár megnyitása, 1 termék"; the checkout header itself shows the "Demó pénztár" label in place of a cart badge while on a checkout page. - expect: The cart page at http://localhost:4401/penztar/kosar still shows the same single line: the previously chosen product, "1 db", "Részösszeg 89 990 Ft", and the H1 "A kosarad".
17. Close the run. - expect: The browser page is closed.
18. Repeat the whole scenario at viewport 390x844 (mobile), starting from a fresh page. - expect: All same expectations apply at 390x844, with two layout-only differences: the catalogue and product pages expose data-testid="purchase-cta" as the visible add control below 1024 px (the inner <button> of data-testid="add-to-cart-button" is not the visible control), and on the delivery step the address-input-* fields are reached by scrolling within the form. The typed values, the redirect URL, the navigation-reason banner text, the empty contact fields, and the cart retention are unchanged.
