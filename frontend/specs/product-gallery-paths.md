# MiBolt product page gallery test plan

## Application Overview

MiBolt is a Hungarian demo storefront: an Angular application served from the Playwright base URL with the in-page MSW mock behind it (no backend, no database). This plan covers one screen — the product page's image gallery — and the row of the standard behind it, `docs/spec/test-scenarios.md` E048 "Use prev/next/thumbnails" → "Correct image/count/alt; stable frame and complete device". It follows one shopper stepping through a phone's photos with the previous and next buttons and the thumbnails, and records what the counter names, which colour the main photo's alt names, which thumbnail is marked current, whether the frame holds its size, and what choosing another colour does to the gallery.

The gallery stepper exists only when a variant carries more than one photo, and the default fixture gives every variant exactly one photo, so `gallery-prev`, `gallery-next` and `gallery-count` are never rendered there — that absence is planned already in `specs/product-detail-paths.md` scenario 1.3 and is not repeated here. This plan therefore runs on the mock scenario `gallery-several-images`, named in the query as `?mi-scenario=gallery-several-images`. Under it every variant of a product shows that variant's own colour photo first and then the product's other colour photos, so a product with four colours shows four photos on every one of its variants. The mock reads the query once when the document loads and keeps that scenario for the page's whole life, so the scenario opens `/telefonok?mi-scenario=gallery-several-images` and reaches the product page by clicking a card; a fresh `page.goto` without the query would load the default scenario's single-photo gallery.

Three facts govern the scenario. First, each test starts in a fresh browser context on the default scenario signed in, and the default fixture serves 55 entries to the catalogue, twelve per page. Second, the same spec runs in both integration viewports, 1920x1080 and 390x844, and the gallery's controls are the same test ids with the same Hungarian labels at both widths — `gallery-main`, `gallery-prev`, `gallery-next`, `gallery-zoom-open`, `gallery-count` and `gallery-thumb-<i>` — so no step has to name a different control per width; what differs per width is only the measured box, and every step that reads a box gives it at both. Third, products are never named by slug or product name: the scenario picks its phone by what the screen shows — the first card without a `product-card-stock` marker whose `product-card-swatches` row holds two or more `product-card-swatch` buttons — and reads the colour names, the counter and the addresses off the screen.

Two measurements shape what the steps assert. The main photo's accessible name is the product's own name followed by the colour of the photo it shows, so each step asserts the colour the alt ends with rather than a fixed string — the alt ends with "Burgundi", "Ezüst", "Fekete" or "Gleccserszín" as the photo changes. The frame `gallery-main` keeps one box while the photo changes: x 48, y 220, 720.4 x 546.8 px at 1920x1080 and x 16, y 308, 343 x 261.75 px at 390x844, measured on all four photos of the pinned product and again after a colour change; the photo inside it is fitted with `object-fit: contain` rather than cropped, which is what keeps the layout still and the whole device visible.

## Test Scenarios

### 1. Product page: gallery

**Seed:** `e2e/seed.spec.ts`

#### 1.1. [E048] the gallery steps through several photos with previous, next and the thumbnails

**File:** `e2e/integration/product-detail-gallery-several-photos.spec.ts`

**Steps:**

1. Open the catalogue on the gallery scenario: `page.goto('/telefonok?mi-scenario=gallery-several-images')` and wait for the grid. - expect: `result-count` reads "55 találat a szűrt feltételek szerint" and twelve `product-card` elements are rendered on the first page — the default "12 / oldal" page size that `catalog-page-size` shows. - expect: The h1 reads "Mobiltelefonok", and the same copy with the same twelve cards is on screen at 1920x1080 and at 390x844; only the layout around them differs. - expect: Every later step reaches its screen by clicking, never with a `page.goto` that drops the query: the mock reads the scenario once when the document loads and keeps it for that page's whole life.
2. Pick the phone by what the screen shows: find the first `product-card` that has no `product-card-stock` element and whose `product-card-swatches` row holds two or more `product-card-swatch` buttons, and click its `product-card-cta`. - expect: On the default fixture's first page that is the third card: the two cards before it render no `product-card-swatches` row at all, and this one's row holds four swatch buttons, so the phone has four colours and its gallery holds four photos. - expect: The control is the card's own `product-card-cta`, labelled "Megnézem" at both widths — at 390x844 a 307 x 40 px bar under the card, at 1920x1080 the card's own link, the same test id and the same text either way. - expect: `product-gallery` is visible and `product-name` is not empty.
3. Read the address bar and the colour selector of the page the card opened. - expect: The address bar reads `/telefonok/<slug>?variant=<id>` and carries no `mi-scenario` parameter: the card navigated inside the app, so the document was never reloaded and the page kept the scenario it loaded with. - expect: `variant-color-group` holds four `variant-color-*` buttons — the four colours the card's swatch row showed — and the pressed one's accessible name ends ", kiválasztva" while the other three end ", elérhető". - expect: On landing the pressed button is `variant-color-burgundi`, whose shown label is "Burgundi".
4. Read the gallery as it stands, before any press. - expect: `product-gallery` holds the frame `gallery-main`, the previous button `gallery-prev` (accessible name "Előző kép"), the next button `gallery-next` ("Következő kép"), the zoom button `gallery-zoom-open` ("Kép nagyítása"), the counter `gallery-count` and four thumbnail buttons `gallery-thumb-0` … `gallery-thumb-3`, whose accessible names read "Ugrás a(z) 1. képre", "Ugrás a(z) 2. képre", "Ugrás a(z) 3. képre" and "Ugrás a(z) 4. képre" inside the list labelled "Galéria indexképei". - expect: `gallery-count` reads "1 / 4": the current photo first, the total second, separated by a spaced slash. - expect: `gallery-prev` is disabled and `gallery-next` is enabled: the first photo is the start of the range. - expect: `gallery-thumb-0` carries `aria-current="true"` and the other three carry `aria-current="false"`; all four carry the class `thumb`, so the current thumbnail is marked by the attribute and not by a class of its own. - expect: The main photo is the `image-photo` image inside `gallery-main`, and its alt ends with the colour the page shows — "Burgundi" on landing — so the alt names the photo's colour rather than its position. No `image-fallback` element is rendered inside the frame. - expect: The frame's box is x 48, y 220, 720.4 x 546.8 px at 1920x1080 and x 16, y 308, 343 x 261.75 px at 390x844. The counter (top left of the frame), the previous, next and zoom buttons (44 x 44 px each) and the four thumbnails (64 x 64 px each, the row starting at the frame's left edge below it) all sit inside that box at both widths. - expect: The photo is fitted, not cropped: the `image-photo` renders with `object-fit: contain` — at 390x844 its box is 325 x 244 px inside the 343 x 262 px frame, its natural size 300 x 600 px — so the whole device is inside the frame.
5. Press `gallery-next` three times, reading the counter, the main photo's alt and the current thumbnail after each press. - expect: After the first press `gallery-count` reads "2 / 4", the alt ends with "Ezüst", `gallery-thumb-1` is the current thumbnail, and both `gallery-prev` and `gallery-next` are enabled. - expect: After the second press the counter reads "3 / 4", the alt ends with "Fekete" and `gallery-thumb-2` is current. - expect: After the third press the counter reads "4 / 4", the alt ends with "Gleccserszín" and `gallery-thumb-3` is current. - expect: The counter moves 1 → 2 → 3 → 4, the alt walks the four colours in the order the mock puts them — the selected colour first, then the phone's other colours: "Burgundi", "Ezüst", "Fekete", "Gleccserszín" — and the current thumbnail moves 0 → 1 → 2 → 3, all three in step with one another. - expect: The frame's box repeats unchanged at every one of the four photos — 720.4 x 546.8 px at 1920x1080, 343 x 261.75 px at 390x844 — so changing the photo never moves or resizes the frame.
6. Try to step past the last photo: press `gallery-next` at "4 / 4". - expect: `gallery-next` is disabled at the last photo, so a press waits on a control that never enables; the counter stays "4 / 4", the alt still ends with "Gleccserszín" and `gallery-thumb-3` is still current. - expect: `gallery-prev` is enabled at the last photo: the range has one end per side.
7. Press `gallery-prev` three times, reading the counter, the alt and the current thumbnail each time. - expect: The presses give "3 / 4" with an alt ending "Fekete" and `gallery-thumb-2` current, then "2 / 4" with "Ezüst" and `gallery-thumb-1`, then "1 / 4" with "Burgundi" and `gallery-thumb-0`: previous walks the same four photos back. - expect: At "1 / 4" `gallery-prev` is disabled again and `gallery-next` is enabled; a further press on the disabled `gallery-prev` leaves the counter at "1 / 4", because the first photo is the end of the range on that side too. - expect: The frame's box is the same at every stop, as in the previous step.
8. Press a thumbnail from a later photo, then another thumbnail from the photo that reaches: press `gallery-thumb-2` from "1 / 4", then `gallery-thumb-0`. - expect: The press on `gallery-thumb-2` ("Ugrás a(z) 3. képre") jumps straight to the third photo: the counter reads "3 / 4", the alt ends with "Fekete", `gallery-thumb-2` becomes the current thumbnail and both `gallery-prev` and `gallery-next` are enabled. The press selects the photo the thumbnail names; it does not step by one. - expect: The press on `gallery-thumb-0` ("Ugrás a(z) 1. képre") returns to "1 / 4" with an alt ending "Burgundi", `gallery-thumb-0` current and `gallery-prev` disabled again. - expect: The main photo is the photo the pressed thumbnail holds: after the press the `image-photo` inside `gallery-main` carries the same source URL as the `image-photo` inside the pressed `gallery-thumb-*` button, and the alt names that photo's colour.
9. Choose another colour while the gallery stands on a later photo: press the colour button `variant-color-ezust`, whose shown label is "Ezüst". - expect: The address bar carries the chosen colour's variant (`?variant=<slug>--ezust--<size>`), the pressed colour button becomes `variant-color-ezust` with an accessible name ending ", kiválasztva", and the other three end ", elérhető". - expect: The gallery restarts at its first photo: `gallery-count` reads "1 / 4", the main photo's alt ends with "Ezüst" — the chosen colour's own photo — `gallery-thumb-0` is current and `gallery-prev` is disabled. A colour press resets the gallery from any stop: measured from the third photo at 1920x1080 and from the fourth photo at 390x844. - expect: The four photos of the new colour are the same set in the same rotation: stepping next reads "2 / 4" with an alt ending "Burgundi", "3 / 4" with "Fekete" and "4 / 4" with "Gleccserszín", so the chosen colour is first and the phone's other colours follow. - expect: The frame's box is unchanged by the colour press — 720.4 x 546.8 px at 1920x1080, 343 x 262 px at 390x844 — and the counter, the buttons and the thumbnails keep their boxes.
10. Read the console and the rendered frame after the walk. - expect: The console holds zero errors and zero warnings. - expect: No `image-fallback` element is rendered inside `gallery-main` at any photo of the walk: every one of the four photos loaded, at both widths.
