# MiBolt product detail page test plan

## Application Overview

MiBolt is a Hungarian demo storefront: an Angular application served from the Playwright base URL with the in-page MSW mock behind it (no backend, no database). This plan covers one screen — the product page a shopper reaches from `/telefonok` by clicking a card (`product-card`, its `product-card-cta`) — and what that shopper sees while choosing a variant and reading a phone's details: the colour and storage selector, the address bar's variant query, the narrow viewport's purchase rail, the specification section, the related products, the way back to the catalogue, and the details block around the choice. The paths that already have scenarios are `specs/storefront-integration.md` (choosing a colour and a storage size in the plain case, an out-of-stock variant refusing the cart, adding to the cart and the header count, the per-line quantity limit) and `specs/shop-edge-paths.md` (a refused cart mutation, an unknown slug and an unknown variant link, the gallery zoom dialog and the message dismiss control, the catalogue from a URL that carries its state, the mobile filter drawer, the demo gate, the header navigation at the mobile width); none of them is repeated here. The gallery's previous/next controls are deliberately not planned: a variant carries one image, so `gallery-prev`, `gallery-next` and `gallery-count` are never rendered.

Three facts govern every scenario. First, each test starts in a fresh browser context: the mock keeps its cart in that context's `sessionStorage`, the demo gate starts signed in on the default scenario, and the default fixture serves 55 entries to the catalogue, twelve per page. Second, the same specs run in both integration viewports, 1920x1080 and 390x844: at 1024 px and wider the add control is the inner button of `add-to-cart-button` and a refusal is the `add-to-cart-reason` hint beside it, while below 1024 px the desktop block inside `.cta-desktop` is `display: none` and the sticky `purchase-rail` carries the price and `purchase-cta`, with the refusal in `purchase-rail-reason`; a step therefore names the mount the viewport shows, and the one scenario whose control exists only at one width says so in its first step. Third, products are never named by slug or product name: a scenario picks its phone by what the screen shows — the first card without a `product-card-stock` marker ("Elfogyott"), or the first in-stock card whose `product-card-swatches` row holds two or more `product-card-swatch` buttons — and reads the slug from the address bar when a later step needs it. Controls built on the `app-button` primitive are host elements carrying the test id, so a press targets the native `button` inside them (`page.getByTestId('<id>').getByRole('button')`); a disabled option is pressed with a forced click, because a plain press waits for a control that will never enable. Every amount, count and Hungarian sentence quoted below is what the default fixture serves for the card the step picks.

Two findings shape what there is to test. The product page's breadcrumb is switched off in this build: `product-breadcrumb` is not rendered at all, so the scenario about the way back to the catalogue asserts that absence and uses the header's own catalogue link rather than inventing a control. The specification section, whose component is named `specification-accordion`, renders always-open boxes: it holds no `details`, no `summary` and no button, so nothing on the screen opens or closes a group and the scenario about it asserts exactly that.

## Test Scenarios

### 1. Product page: variants and details

**Seed:** `e2e/seed.spec.ts`

#### 1.1. a colour whose storage sizes differ leaves the size it does not come in refused, with the reason text

**File:** `e2e/integration/product-detail-colour-storage-diff.spec.ts`

**Steps:**

1. Open `/telefonok` and wait for the grid. - expect: `result-count` reads "55 találat a szűrt feltételek szerint". - expect: Twelve `product-card` elements are rendered, the default "12 / oldal" page size. - expect: At least one `product-card` with NO `product-card-stock` marker carries a `product-card-swatches` row of two or more `product-card-swatch` buttons.
2. Open that first such card: click the `product-card-cta` of the first `product-card` that has no `product-card-stock` marker and whose `product-card-swatches` row holds at least two swatches. Note the slug from the address bar. - expect: `product-page` is visible and `product-name` is not empty. - expect: The address bar reads `/telefonok/<slug>?variant=<id>`: the card's shown variant travels in the query. - expect: `variant-color-group` holds four `variant-color-*` buttons and `variant-storage-group` two `variant-storage-*` buttons. - expect: The legends read "Szín: Burgundi" and "Tárhely: 256 GB"; the pressed colour button's accessible name ends ", kiválasztva" and the three others end ", elérhető". - expect: Both size buttons are enabled and neither group renders a reason paragraph (0 `.reason` elements in each). - expect: `product-stock` reads "Raktáron a demó készletben" and the "Készülékár" block's `price-amount` reads "599 990".
3. Press the colour buttons one after another — `variant-color-ezust`, then `variant-color-fekete` — reading the storage group after each press. - expect: After `variant-color-ezust` the colour legend reads "Szín: Ezüst", the amount "608 990", the storage legend still "Tárhely: 256 GB", and the storage group still renders 0 reason paragraphs. - expect: After `variant-color-fekete` the colour legend reads "Szín: Fekete", the amount "617 990", and the storage group still renders 0 reason paragraphs: neither of these colours leaves a size out.
4. Press `variant-color-gleccserszin` and read both groups. - expect: The colour legend reads "Szín: Gleccserszín" and the "Készülékár" amount reads "626 990". - expect: The storage legend still reads "Tárhely: 256 GB": the chosen size survives the colour change. - expect: `variant-storage-512` is now disabled and carries `aria-describedby="variant-storage-disabled-512"`, while the chosen `variant-storage-256` stays pressed and enabled. - expect: `variant-storage-group` renders exactly one reason paragraph, reading "Ez a szín (Gleccserszín) nem elérhető 512 GB kapacitással." - expect: `variant-color-group` renders no reason paragraph (0 elements): the refusal belongs to the size this colour does not come in, not to the colour.
5. Press the disabled `variant-storage-512` with a forced click (a plain press would wait forever on a disabled control). - expect: Nothing changes: the legends still read "Szín: Gleccserszín" and "Tárhely: 256 GB", and the amount is still "626 990". - expect: The address bar still reads `/telefonok/<slug>?variant=<slug>--gleccserszin--256`.
6. Press `variant-color-burgundi` and read the storage group again. - expect: The size is available again: `variant-storage-512` is enabled, carries no `aria-describedby`, and the storage group renders 0 reason paragraphs. - expect: The storage legend still reads "Tárhely: 256 GB" and the amount is back to "599 990".

#### 1.4. the address bar carries the chosen variant, and opening that address in a fresh page restores it

**File:** `e2e/integration/product-detail-variant-url.spec.ts`

**Steps:**

1. Open `/telefonok` and wait for the grid. - expect: `result-count` reads "55 találat a szűrt feltételek szerint" and twelve `product-card` elements are rendered.
2. Open the first in-stock card whose `product-card-swatches` row holds two or more swatches, through its `product-card-cta`. - expect: `product-page` is visible and the address bar reads `/telefonok/<slug>?variant=<id>`. - expect: The legends read "Szín: Burgundi" and "Tárhely: 256 GB", their pressed buttons carry `variant-color-burgundi` and `variant-storage-256`, and the "Készülékár" amount reads "599 990". - expect: Note the slug and the two pressed buttons: a variant id is `<slug>--<colour code>--<size>`.
3. Press `variant-color-fekete`. - expect: The address bar carries `?variant=<slug>--fekete--256`, built from the slug, the pressed colour button's code and the pressed size. - expect: The colour legend reads "Szín: Fekete" and the "Készülékár" amount reads "617 990".
4. Press `variant-storage-512`. - expect: The address bar carries `?variant=<slug>--fekete--512`. - expect: The storage legend reads "Tárhely: 512 GB", the amount "717 990" and `product-stock` "Raktáron a demó készletben". - expect: The one refusal that belongs to this size is rendered: `variant-color-gleccserszin` is disabled under the reason "Ez a szín (Gleccserszín) nem elérhető 512 GB kapacitással."
