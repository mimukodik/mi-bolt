- [ ] Add a named failing test for EACH criterion below to the owned spec files, before its implementation. UI criteria require rendered DOM/user-action assertions; API criteria require actual SDK requests intercepted by MSW.

## Strict task-specific acceptance criteria

- [ ] **T25-AC01** All four families and five checkout states have no page-level horizontal overflow at 320,390,768,1024,1440,1920 CSS px.
- [ ] **T25-AC02** Compare generated screenshots to supplied reference composition and tokens. Record necessary deviations: MiBolt live name, accessible dark orange-button labels, no fake operator promises or omitted-scope nav.
- [ ] **T25-AC03** Keyboard completes browsing→variant→cart→checkout→success; drawer/zoom/terms manage focus and restore it.
- [ ] **T25-AC04** Check 200% text enlargement, reduced motion, narrow reflow, 44px shopping targets, contrast and sticky-CTA focus visibility.
- [ ] **T25-AC05** Automated axe results and manual keyboard checks are separate evidence; do not claim a WCAG certificate from screenshots or static validation.

## Strict shared acceptance criteria

- [ ] **T25-G01** Read the resolved external mi-bolt-design/SKILL.md and its task-relevant references before implementation AND independently before verification. Record skill version, R01–R26 applicability, files, viewports and evidence in the task review.
- [ ] **T25-G02** Use the resolved latest stable Angular 22.x only; no SSR, prerendering, hydration, NgModule-based application structure, zone.js or legacy structural directives.
- [ ] **T25-G03** For UI/state changes use Angular signals, signal inputs/outputs and built-in template control flow. Consume API data exclusively through the generated SDK and MSW boundary.
- [ ] **T25-G04** All applicable unit and E2E acceptance scenarios are automated against deterministic mocks. New shared/browser runtime files must appear in both coverage manifests, including unexecuted files. Node-only targets must appear in their separate 100% unit and black-box command/integration coverage manifests; no silent exclusions.
- [ ] **T25-G05** No live business API, telemetry, remote font, payment, email or SaaS request; no test skip/focus, coverage-ignore comment, threshold reduction or hidden generated-file editing.
- [ ] **T25-G06** Attach fresh command output, task-specific assertions and design evidence. Planned checks are not passing checks. Leave the task unaccepted when any assertion fails.
