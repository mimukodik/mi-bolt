## Strict task-specific acceptance criteria

- [ ] **T01-AC01** Official Angular CLI application builder and standalone bootstrap build successfully; strict mode and strictTemplates are enabled.
- [ ] **T01-AC02** No server.ts, main.server.ts, app.config.server.ts, @angular/ssr, platform-server dependency, prerender target or zone.js polyfill exists.
- [ ] **T01-AC03** Use Angular signals and @if/@for/@switch with stable track identity in authored templates; static lint disallows *ngIf/*ngFor/*ngSwitch and legacy @Input/@Output in authored application code.
- [ ] **T01-AC04** Provide hu-HU locale and HttpClient. An explicit environment distinguishes demo and e2e builds; neither has a real-backend fallback.
- [ ] **T01-AC05** The app boots under / with meaningful title and a fatal startup surface; no business feature is faked directly in a component.

## Strict shared acceptance criteria

- [ ] **T01-G01** Read the resolved external mi-bolt-design/SKILL.md and its task-relevant references before implementation AND independently before verification. Record skill version, R01–R26 applicability, files, viewports and evidence in the task review.
- [ ] **T01-G02** Use the resolved latest stable Angular 22.x only; no SSR, prerendering, hydration, NgModule-based application structure, zone.js or legacy structural directives.
- [ ] **T01-G03** For UI/state changes use Angular signals, signal inputs/outputs and built-in template control flow. Consume API data exclusively through the generated SDK and MSW boundary.

New shared/browser runtime files must appear in both coverage manifests, including unexecuted files. - [ ] **T01-G05** No live business API, telemetry, remote font, payment, email or SaaS request; no test skip/focus, coverage-ignore comment, threshold reduction or hidden generated-file editing.
