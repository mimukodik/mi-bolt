## Strict task-specific acceptance criteria

- [ ] **T05-AC01** Await persistence hydration and worker.start() before bootstrapApplication; render explicit retryable fatal state if registration/startup fails.
- [ ] **T05-AC02** Use the same handler factory in setupWorker and setupServer. Clock, IDs, delays and repository are injected, never unseeded randomness.
- [ ] **T05-AC03** Persist only allowlisted non-PII snapshot fields in tab-scoped sessionStorage; clear malformed/expired/version-mismatched snapshots safely. Storage-denied mode remains functional in memory and announces no reload persistence.
- [ ] **T05-AC04** Contact, address, draft, pending intent and raw idempotency payloads are not serialized. Persist privacy-minimized committed order receipts and order-key digests for uncertain-response recovery.
- [ ] **T05-AC05** Unknown API endpoints cannot pass through; local app/media assets are explicitly allowed. External scripts, fonts, telemetry and business hosts are disallowed.
- [ ] **T05-AC06** E2E scenario descriptor is read before worker setup, absent from demo UI, and creates an isolated repository for each test/context; controlled reload tests retain their own snapshot only.

## Strict shared acceptance criteria

- [ ] **T05-G01** Read the resolved external mi-bolt-design/SKILL.md and its task-relevant references before implementation AND independently before verification. Record skill version, R01–R26 applicability, files, viewports and evidence in the task review.
- [ ] **T05-G02** Use the resolved latest stable Angular 22.x only; no SSR, prerendering, hydration, NgModule-based application structure, zone.js or legacy structural directives.
- [ ] **T05-G03** For UI/state changes use Angular signals, signal inputs/outputs and built-in template control flow. Consume API data exclusively through the generated SDK and MSW boundary.
- [ ] **T05-G04** All applicable unit and E2E acceptance scenarios are automated against deterministic mocks. New shared/browser runtime files must appear in both coverage manifests, including unexecuted files. Node-only targets must appear in their separate 100% unit and black-box command/integration coverage manifests; no silent exclusions.
- [ ] **T05-G05** No live business API, telemetry, remote font, payment, email or SaaS request; no test skip/focus, coverage-ignore comment, threshold reduction or hidden generated-file editing.
- [ ] **T05-G06** Attach fresh command output, task-specific assertions and design evidence. Planned checks are not passing checks. Leave the task unaccepted when any assertion fails.
