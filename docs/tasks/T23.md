## Strict task-specific acceptance criteria

- [ ] **T23-AC01** COD commits directly; card first creates mock intent, then only succeeded allows order. Declined remains on review with retry/change-method actions.
- [ ] **T23-AC02** Pending intent uses GET polling every 1 second for at most 10 attempts with deterministic clock; timeout yields recoverable unknown state, not success or failure claim.
- [ ] **T23-AC03** Double-click, browser retry and timeout-after-commit produce exactly one order/stock decrement. Exhaust in-flight submit, do not cancel a write to start another.
- [ ] **T23-AC04** Unknown outcome retains identical order key and normalized request; reload recovery queries stored receipt or replays exact order request without persisting contact/address.
- [ ] **T23-AC05** Expected failure leaves inputs/cart intact. Logs omit contact/address and payment-like data.
