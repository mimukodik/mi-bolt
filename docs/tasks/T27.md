## Strict task-specific acceptance criteria

- [ ] **T27-AC01** UNIT: every owned runtime executable file has exactly 100% statements, branches, functions and lines; no uncovered source omitted from denominator.
- [ ] **T27-AC02** E2E: independent Chromium browser source coverage for the same browser-delivered owned runtime has exactly 100% in all four metrics; never merge with unit counters.
- [ ] **T27-AC03** 100% of scenario rows and component-state requirements have passing assertions. Coverage measures execution, not correctness, so negative assertions and boundary cases are mandatory.
- [ ] **T27-AC04** Chromium/Firefox/WebKit run the complete applicable business scenario suite against MSW. Chrome-derived JS coverage is not falsely reported as cross-browser code coverage.
- [ ] **T27-AC05** Run test-order randomization and repeat the release suite three times with retries disabled; no skip/todo/only, flaky quarantine or lowered threshold.
- [ ] **T27-AC06** Every deliberate failure expected by a scenario is asserted; unexpected console errors, schema errors, unhandled calls, missing artifact or external egress fail the run.

## Strict shared acceptance criteria

- [ ] **T27-G01** Read the resolved external mi-bolt-design/SKILL.md and its task-relevant references before implementation AND independently before verification. Record skill version, R01–R26 applicability, files, viewports and evidence in the task review.
- [ ] **T27-G02** Use the resolved latest stable Angular 22.x only; no SSR, prerendering, hydration, NgModule-based application structure, zone.js or legacy structural directives.
- [ ] **T27-G03** For UI/state changes use Angular signals, signal inputs/outputs and built-in template control flow. Consume API data exclusively through the generated SDK and MSW boundary.
- [ ] **T27-G04** All applicable unit and E2E acceptance scenarios are automated against deterministic mocks. New shared/browser runtime files must appear in both coverage manifests, including unexecuted files. Node-only targets must appear in their separate 100% unit and black-box command/integration coverage manifests; no silent exclusions.
- [ ] **T27-G05** No live business API, telemetry, remote font, payment, email or SaaS request; no test skip/focus, coverage-ignore comment, threshold reduction or hidden generated-file editing.
- [ ] **T27-G06** Attach fresh command output, task-specific assertions and design evidence. Planned checks are not passing checks. Leave the task unaccepted when any assertion fails.
