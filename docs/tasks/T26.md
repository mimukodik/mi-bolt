## Strict task-specific acceptance criteria

- [ ] **T26-AC01** Exactly all 16 operationIds map to handlers and SDK transport tests; missing/extra business routes fail the contract suite.
- [ ] **T26-AC02** Validate every request/response at test boundary against OpenAPI schema and every documented business error code against operation behavior.
- [ ] **T26-AC03** Include missing required header, wrong type, quantity overflow, stock conflict, stale version/quote, reused key and conditional-address/payment violations.
- [ ] **T26-AC04** Demo and Node mock share the same domain implementation; browser and Node fixtures produce equivalent responses for equivalent session/clock/state.
- [ ] **T26-AC05** Changing a schema fixture incompatibly makes at least one contract test fail; generated interfaces alone are not accepted as runtime validation.
