## Strict task-specific acceptance criteria

- [ ] **T09-AC01** Only demo_card and demo_cod exist. No bank-card fields or third-party payment requests are accepted.
- [ ] **T09-AC02** Card succeeds/declines/remains pending via deterministic scenarios; a succeeded intent must match cart, quote, amount and session. COD forbids a paymentIntentId.
- [ ] **T09-AC03** Atomic order commit checks consent/version/stock/expiry, decrements simulated stock once, stores receipt plus idempotency replay and marks cart ordered.
- [ ] **T09-AC04** A timeout-after-commit followed by exact key/body retry returns the same order without decrementing stock twice; different body with reused key returns 409.
- [ ] **T09-AC05** Reload can recover the same privacy-minimized receipt. Contact/address are absent from persisted receipt, logs and browser screenshot evidence.
- [ ] **T09-AC06** Success copy explicitly says no real payment, order transmission, email or delivery occurred.
