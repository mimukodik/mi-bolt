# FIX-03 — Wire Prettier to ESLint and add the format scripts

Status: PLANNED — not executed.
Severity: major
Source: A1 D1

## Why this is wrong

The user asked for this directly: *"Lintet is állitsd be strict -re és legyen prettierrel
összekötve"* — set lint to strict **and have it wired together with Prettier**. Prettier
is installed and configured, but nothing connects it to ESLint and nothing can prove a
file is formatted. `eslint-config-prettier`, the package whose whole job is to switch off
the ESLint rules that fight Prettier, is absent from `package.json`. There is no `format`
script and no `format:check` script, so formatting compliance is not something any gate,
hook or reviewer can check — it is a convention with no enforcement.
`docs/spec/testing.md:107-131` lists the project's command surface as a pipeline; a
formatting check that exists in nobody's command list cannot be part of it.

## Evidence

`.prettierrc` exists and is configured — so a formatting standard is declared:

```json
{
  "printWidth": 100,
  "singleQuote": true,
  "overrides": [
    {
      "files": "*.html",
      "options": {
        "parser": "angular"
      }
    }
  ]
}
```

`package.json:35-57` — the whole `devDependencies` block. `prettier` is there at
`:52` (`"prettier": "^3.8.1"`, resolved 3.9.6, read from
`node_modules/prettier/package.json`). **`eslint-config-prettier` is not in the list.**
Confirm with `ls node_modules/eslint-config-prettier`, which returns
`No such file or directory`.

`package.json:4-20` — the whole `scripts` block. There are sixteen scripts; eleven is the
count **after** FIX-47 prunes, and two of those eleven are the ones this task adds.
**Neither `format` nor `format:check` is among them.** Confirm with
`grep -c '"format' package.json`, which prints `0`.

`eslint.config.js:8-16` extends `tseslint.configs.stylistic`, a preset of purely
stylistic rules. With nothing switching those off, ESLint and Prettier are two
formatters aimed at the same files with no declared precedence between them.

There is no `.prettierignore` in the repository (`ls .prettierignore` →
`No such file or directory`), so `prettier --check .` would today sweep
`src/app/api/generated/**` — all 56 files, every one of which `npm run api:drift` deletes and
regenerates (`scripts/api-drift.mjs:96-101`); 27 of them come back changed today, because those
27 have lost their `/* eslint-disable */` header. Reformatting generated output is how a green
`api:drift` turns red on the next run.

Note on the guidance this task follows, and why: `eslint-config-prettier` placed **last**
in the flat config array is the current recommended wiring, and `eslint-plugin-prettier`
(running Prettier as an ESLint rule) is discouraged by Prettier's own projects. Sources:
`https://github.com/prettier/eslint-config-prettier`,
`https://github.com/prettier/eslint-plugin-prettier`.

## What to change

Four files, one of them new.

### 1. `package.json` — add the dependency

```bash
npm install --save-dev eslint-config-prettier
```

Do not hand-edit the dependency into `package.json`; run the command so
`package-lock.json` is updated in the same commit. Record the exact resolved version in
the commit body, read from `node_modules/eslint-config-prettier/package.json`. Do not
write a version number into this task file's expectations — the resolved version is
whatever npm installs on the day this runs, and inventing one would be a number with no
source (`.claude/rules/planning-deliverables.md`).

### 2. `package.json` — add the two scripts

Add these two entries to the `scripts` object, after `"lint"`:

```json
    "format": "prettier --write .",
    "format:check": "prettier --check ."
```

Prettier's `--ignore-path` already defaults to `[.gitignore, .prettierignore]`
(`node_modules/.bin/prettier --help`), and `.gitignore` already excludes `node_modules`,
`dist`, `coverage`, `playwright-report/` and `.angular/`, so the bare `.` argument is
safe for those.

### 3. `.prettierignore` — new file at the repository root

```text
# Generated by ng-openapi-gen; reformatting it makes `npm run api:drift` fail.
src/app/api/generated/

# Generated by MSW tooling.
public/mockServiceWorker.js

# The specification. `docs/` is what every task in docs/fix/ cites by line
# number, and docs/index.html cannot be formatted at all: .prettierrc parses
# *.html with the Angular parser, which rejects that file's final inline
# <script> — `prettier --check docs/index.html` exits with
# `SyntaxError: Unexpected character "EOF" … (5390:24)`, which no reformat
# clears. Measured 2026-09-17 with prettier 3.9.6.
docs/

# Agent configuration and the installed mi-bolt-design skill. FIX-38 pins the
# SHA-256 of .claude/skills/mi-bolt-design/SKILL.md against the SHA256SUMS.txt
# shipped beside it; reformatting the file changes one and not the other, and
# .claude/CLAUDE.md makes the installed copy the only authority.
.claude/
.agents/
.codex/
.gemini/
```

Both entries have a reason and neither is a convenience exclusion: the generated SDK is
rewritten byte-for-byte by `npm run api:generate`, and `api:drift` compares that output
against what is committed. The four trees added above are not convenience exclusions
either, and each carries its reason in the file: `docs/` is the specification this whole
package cites by line number and contains one file Prettier cannot parse; `.claude/`,
`.agents/`, `.codex/` and `.gemini/` are agent configuration, and
`.claude/skills/mi-bolt-design/` is an externally installed package whose bytes **FIX-38**
hashes. `CLAUDE.md`, `AGENTS.md` and `README.md` at the repository root are **not**
ignored: all three are already Prettier-clean, so the sweep does not touch them and a
later edit to any of them is expected to stay clean.

If `npm run format:check` reports a path with no inferred parser, add that path to this
file with a one-line reason above it. Do **not** add `--ignore-unknown` to the scripts:
that flag silently skips every file type Prettier does not yet understand, including ones
it will understand after the next upgrade, whereas an ignore entry is a decision someone
can read and argue with.

### 4. `eslint.config.js` — append the config, last in the array

First settle which entry point the installed package publishes:

```bash
grep -A6 '"exports"' node_modules/eslint-config-prettier/package.json
```

If the `exports` map lists a `"./flat"` subpath, require that one; otherwise require the
package root. The two possibilities are:

```js
const eslintConfigPrettier = require('eslint-config-prettier/flat');
```

```js
const eslintConfigPrettier = require('eslint-config-prettier');
```

Put the `require` beside the other four at `eslint.config.js:2-5`, and append the config
as the **last element** of the array passed to `defineConfig`, after the `**/*.html`
block that currently ends at `:81`:

```js
  eslintConfigPrettier,
]);
```

**Last is the whole point.** A flat config array applies later entries over earlier ones,
so `eslint-config-prettier` only switches off the conflicting rules if nothing comes
after it. Placing it anywhere else leaves the conflict in place while looking like it was
fixed.

### 5. Reformat whatever `prettier --write .` changes

Run `npm run format` once and commit the result **in this same commit**. Before running
it, confirm the ignore file is in place and doing its job:
`./node_modules/.bin/prettier --check docs/index.html` must print
`[error] docs/index.html: SyntaxError` **only** when the path is named explicitly, and
`npm run format:check` must not name any path under `docs/`, `.claude/`, `.agents/`,
`.codex/` or `.gemini/`. If it does, `.prettierignore` was not written as item 3
specifies — stop and fix that before sweeping, because the sweep is not reversible
with a git verb in this workspace.

The repository has never had a format gate, so an unknown number of files will change; do
not write a number into the plan before running it. Two rules for that pass:

- Every file it rewrites is inside this commit. A format sweep split across two commits
  leaves `format:check` red in between.
- `.claude/rules/code-standards.md` limits a formatting sweep to files this session
  changed. That limit is lifted here **only because this task's entire subject is
  introducing the format gate**: a gate that is red the moment it is added is not a gate.
  Say so in the commit body, and list the count of files the sweep rewrote.

## Out of scope

- **`lintFilePatterns` — FIX-01.** Must already be in place or `npm run lint` will not
  start and the wiring cannot be verified.
- **Rule severities, the type-aware presets and the `src/app/shared/ui/**` override —
  FIX-02.** Do not change a rule's severity in this task and do not remove a rule. The
  only edit to `eslint.config.js` here is one `require` and one array element appended at
  the end.
- **`eslint-plugin-prettier`.** Not installed, not to be installed. Prettier-as-an-ESLint-rule
  is the approach both upstream projects advise against, and it would make every
  formatting difference an ESLint error with a source location, which is slower and
  noisier than running Prettier directly.
- **Editing `.prettierrc`.** The declared style stays exactly as it is. This task
  enforces the existing standard, it does not renegotiate it.
- **Any behavioural change to a source file.** A reformat changes whitespace, quotes and
  line breaks only. If `npm run build` or `npm run test` changes result after the sweep,
  something other than formatting was changed; find it and undo that part.
- **`tests/**`, `e2e/**` and `scripts/**` in `lintFilePatterns`.** Prettier does format
  them (they are not in `.gitignore`), and that is correct and intended; ESLint's reach
  is a separate question that FIX-06 and FIX-46 bear on.

## How to verify

From the repository root, npm only, in this order.

1. `npm run format:check`

   Must exit **0** and print `All matched files use Prettier code style!` If it exits `1`
   it lists the unformatted files; run `npm run format` and commit those changes.

2. `npm run lint`

   Must exit **0** and print `All files pass linting.` This is the proof that the wiring
   did what it is for: the stylistic rules that could disagree with Prettier are now off,
   so a Prettier-formatted file is also a lint-clean file.

3. `npm run build` — must exit **0**.

4. `npm run test` — run before this task's first edit and again after its last; record
   both exit codes and both failure lists in the commit body and confirm they are
   identical, per **FIX-03-AC06**. A red suite that is red in exactly the same way
   before and after satisfies this step; **FIX-04** owns making it green.

5. `npm run api:drift` — must exit **0** *and* leave the working tree clean for the
   generated SDK. Check with `git status --short src/app/api/generated/`, which must
   print nothing. This is the criterion that proves `.prettierignore` did its job: after
   the sweep, `git status --short` lists no path under `src/app/api/generated/`, `docs/`,
   `.claude/`, `.agents/`, `.codex/` or `.gemini/`, and `public/mockServiceWorker.js` is
   unchanged. **Be aware that this command deletes and regenerates all 56 files under
   `src/app/api/generated/`, of which 27 come back changed today; that is expected here
   and the point of the check is that the regenerated bytes match what is
   committed.** Do not run it casually while working on any other task.

6. Confirm the ordering:
   `grep -n "eslintConfigPrettier" eslint.config.js` must return exactly two lines, the
   `require` near the top and the array element, and the array element's line number must
   be greater than that of every other element in the array.

`npm run lint` is expected to already be green by the time this task runs — FIX-01 and
FIX-02 own getting it there, and step 2 above is this task's own proof that wiring
Prettier in did not break it. `npm run test` is not gated by this task: **FIX-04** owns
the suite's baseline failures, and step 4 above records rather than requires a green run,
per **FIX-03-AC06**. The one gate that stays red
for a reason this task does not fix: `npx playwright test` (**FIX-09**). Do not run it
while working on this task: it rewrites 49 screenshots under
`e2e/design/screenshots/` and leaves the working tree dirty. `npm run api:drift` is not
deferred — it **is** run in this task, at step 5 above, because proving it detects drift
is this task's own subject.
